The problem

Why Agentic Systems Break the Playbook

Property 1

Non-deterministic

Same input, a different answer every time. You cannot assert == — traditional pass/fail tests simply don't apply to the interesting behavior.

→ Part 1 · Testing solves this.

Property 2

Long-running & stateful

A task is a sequence of steps, not one request. A crash mid-run loses real work — not just a connection.

→ Part 2 · Deployment solves this.

Part 1 · Testing

One System, Validated Four Ways

Same system, same dataset, same judge model — the only variable is the harness. It's a buy-vs-build decision.

Build our own

Custom pytest

Total control, zero cost, fully private. Every metric and judge prompt is yours — but you maintain it.

Hosted

LangSmith

Dashboards, history, free per-node traces. The price: data leaves the machine.

Off-the-shelf

deepeval / promptfoo

Fast to adopt, rich prebuilt rubrics. The abstraction can hide what's actually measured.

Deployment: The Landscape

Managed = speed & convenience. Self-hosted = control & privacy, at the cost of building the resilience machinery yourself.

Managed platform

LangSmith / LangGraph Platform

Hosted agent server — durable state and streaming handled for you. Fastest path; vendor lock-in + Enterprise license to self-host the server.

Managed platform

Google ADK

Google's managed agent runtime (Vertex Agent Engine). Cloud-native, scales for you — ties you to GCP.

Self-hosted

Roll our own

Full control and privacy. You must solve durability, streaming, and failover — the next slides show how.

Part 2 · Deployment

The Self-Hosting Challenge: Life Without Redis

The problem

Streaming is glued to execution

A single node couples graph execution and the client's live stream into one process.

Behind a load balancer, the node a user is watching may not be the node doing the work — and there's no way to relay updates between them. The connection drops, the live view dies.

The fix

Redis pub/sub decouples them

A channel per run separates "who streams to the user" from "who executes the agent." Any node can relay any run.

Pair it with durable state (Postgres checkpoints) so a dead executor can be resumed — Redis alone fixes streaming, not execution recovery.

Part 2 · Deployment

The Payoff: Surviving a Crash

Kill the node running a live debate — another node picks it up mid-sentence and finishes it. The user never notices.
Failure mode 1

You lose your screen

The client disconnects, but the executor is fine. Redis re-attach — reconnect to the same run's channel.

Failure mode 2

You lose the worker

The executing node dies. Its heartbeat goes stale, another node claims ownership and resumes from the Postgres checkpoint.

What transfers to every agent we build
An agent isn't ready when it works —
it's ready when it's measurable and survivable.
TRUST
Define dimensions → split deterministic vs. judge → gate releases automatically.
RESILIENCE
Durable state + streaming decoupled with Redis + automatic failover.
